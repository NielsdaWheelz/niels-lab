Reading-first knowledge management system with semantic search, persistent anchoring, and LLM-augmented conversation. Built as the week 3 group project at Fractal with Nyan and Jahnik.

## what I built

A complete document management and semantic search system built as a production specification. You upload documents (PDF, EPUB, HTML), highlight text, and search across everything you've saved using AI-powered similarity search. The core innovation is **persistent anchoring**—highlights use byte offsets into canonical text that survive document re-ingestion via fuzzy text matching, so your annotations never get lost when you update a file.

The system enforces privacy-first design: all data is indexed by user ID, search results respect ACLs, and every resource uses prefixed typed IDs (`doc_`, `hl_`, `conv_`, `msg_`, etc.) for type safety at the API boundary.

**What it does:**
1. Upload documents → deterministic canonical text extraction (same file always produces identical UTF-8 output)
2. Highlight & annotate → anchors stored as byte offsets into canonical text that survive re-extraction via fuzzy text matching
3. Semantic search → hybrid BM25 + pgvector-powered similarity search with ACL enforcement
4. Chat with documents → LLM conversations with RAG pipeline that retrieves relevant chunks and injects context (V1.0 complete)

## architecture

**Core Design Principles**

1. **Canonical Text** - Deterministic UTF-8 transformation of PDFs, EPUBs, HTML into immutable byte arrays with stable offsets. Same file always produces identical text.

2. **Persistent Anchoring** - Highlights store byte offsets into canonical text (not original file). When documents are re-ingested, the system detects hash changes and remaps anchors via fuzzy text matching (up to 10% edit distance).

3. **Privacy Enforcement** - All access control derives from `Visible(U, O)` predicate. Every database query filters by user_id. Unknown or forbidden resources return 404 (not 403) to prevent existence leaks.

4. **Typed IDs** - All external API resources use prefixed IDs (`doc_`, `hl_`, `conv_`, `msg_`, `cnk_`, `ann_`, `rdr_`, `lnk_`) for type safety.

5. **Async Ingestion** - Redis + Celery handles background jobs: text extraction, chunking, embedding generation, anchor remapping on re-ingestion.

**API Overview**

All endpoints require Clerk JWT (except `/health`). Key endpoints:

- `POST /documents` - Upload document (triggers async ingestion pipeline)
- `GET /documents` - List documents (paginated)
- `GET /documents/{id}/chunks` - List document chunks with embeddings
- `POST /highlights` - Create highlight (byte-offset anchor into canonical text)
- `POST /search` - Hybrid search (BM25 + vector, ACL-filtered)
- `GET /conversations`, `POST /conversations/{id}/messages` - Chat threads with RAG context
- `GET /health` - Health check (no auth required)
