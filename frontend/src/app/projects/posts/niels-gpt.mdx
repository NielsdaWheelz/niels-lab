A tiny, end-to-end LLM pipeline. Tokenizer → cache → pretrain → SFT → kv-cache inference → chat CLI. Minimal dependencies. Strict guardrails. Laptop-first.

This is not a frontier model. It's a **complete** model *system*.

## what I shipped

- **tokenizer training** - SentencePiece unigram with byte fallback, project-specific sentinel chat tokens, and collision checks
- **data ingestion** - HF datasets (Wikitext, FineWeb-Edu, OASST1, Dolly) + local Roam markdown + local "primer" text
- **caching** - token caches written to disk with metadata, including tokenizer SHA; training hard-fails on mismatch
- **model** - decoder-only transformer with RoPE, RMSNorm, SwiGLU, weight tying
- **training** - AdamW, warmup + cosine LR, grad clipping, optional AMP on MPS, optional activation checkpointing
- **inference** - both naive autoregressive generation *and* kv-cache `prefill` + `decode_step` (with optional attention row tracing)
- **ops hygiene** - resolved settings written per run; checkpoint sidecars carry provenance; config coverage audit exists

If you want the full beginner deep-dive, it's in `WALKTHROUGH.md`. This post is the executive/technical narrative.

## design constraints

- **hardware reality** - I wanted this to run on a Mac (MPS) or CPU. That means embracing constraints instead of pretending CUDA is "default"
- **debuggability over magic** - I'd rather write 200 lines of explicit code than import a framework that makes it impossible to prove invariants
- **reproducibility as a feature** - caches and checkpoints should tell you *exactly* what created them. Mismatches should crash early, loudly, and descriptively

## architecture in one pass

### tokenizer: text becomes ids (and the tokenizer can't silently drift)

I use SentencePiece unigram with `byte_fallback=True`, then I bolt on explicit chat structure via four sentinel tokens:

- `sys` / `usr` / `asst` / `eot`

Two non-negotiables here:

- **the sentinels must encode to exactly one token ID** - otherwise chat formatting becomes ambiguous and masking breaks
- **raw text must never contain the sentinel strings** - otherwise you're training on "control plane" tokens accidentally

So the loaders and cache builders hard-fail on collisions and validate the special IDs.

Why the ugly UUID suffix? Because "hope no one types `<|system|>`" is not a strategy.

### caching: I refuse to pay the tokenization tax every epoch

Tokenization is pure overhead once you trust your tokenizer. So I write token shards to disk and train against memory-mapped arrays.

- **pretrain caches** - sharded `uint16` token bins + `meta.json`
- **SFT caches** - concatenated tokens + offsets (`idx.npy`) + `meta.json`

The cache metadata includes the tokenizer SHA. Training refuses to load caches produced by a different tokenizer. This is one of those boring correctness details that saves you from "mysteriously worse" runs.

### model: small, modern transformer choices (no nostalgia)

The core is the standard decoder-only transformer, but with choices that reflect what actually works in 2024–2025 small-scale training:

- **RoPE** - better positional generalization than learned absolute embeddings in practice
- **RMSNorm (pre-norm)** - stable, simple, fast; avoids post-norm fragility
- **SwiGLU** - good quality-per-flop; common in modern open models
- **weight tying** - fewer params, usually a small perplexity win

This is intentionally not "every trick in the literature". It's the minimum modern set you can defend.

### training: minimal loop, strict invariants

Pretraining is next-token prediction on mixed sources. SFT is next-token prediction with **loss masked to assistant spans** (everything else gets `ignore_index=-100`).

The training loop is direct: sample windows → forward → cross entropy → backward → clip → step. LR is warmup then cosine decay. Checkpointing is phase-scoped and reproducible.

## the parts I'm quietly proud of

### the configuration system is strict (by design)

Here, defaults live in `niels_gpt/settings.py`, validation is handled by Pydantic, and each run writes:

- `runs/<run_id>/resolved_settings.json`

Then checkpoints carry sidecars pointing back to the resolved settings. If you care about reliability, provenance is not optional.

Also: the repo has an explicit config audit tool (`tools/audit_config_coverage.py`) that exists to prevent "random hyperparameter literals" from creeping into code.

### kv-cache inference is first-class, not an afterthought

If you've ever watched someone "implement inference" by recomputing the whole forward pass for every generated token, you know the pain.

So inference is split cleanly into:

- **prefill** - run the prompt once, fill `k/v` for every layer
- **decode_step** - append one token, do attention over cached keys/values

And because I wanted introspection, the cache path can optionally return an **attention probability row** for a selected layer (last-token attention across heads). It's a cheap debugging hook that pays for itself the first time you're diagnosing weird loops.

### benchmarking is automated, not vibes

The repo includes `tools/bench_sweep.py`: it runs training-loop microbenchmarks in subprocesses, detects OOM/timeout, searches for max microbatch, and writes a ranked summary (`bench/summary.md`) with throughput and estimated 8-hour tokens.

This is the workflow I want: pick a config based on measured constraints, not on folklore.

## how to run it

1. Build caches (accept that HF datasets are network-bound the first time)
2. Pretrain with a profile or a config override
3. SFT
4. Chat

Example (profiles exist):

```bash
python -m train.run --list-profiles
python -m train.run --phase pretrain --profile prod --device mps
python -m train.run --phase sft --profile prod-sft --device mps
python -m niels_gpt.chat_cli --ckpt checkpoints/best.pt
```

If you want a pretrained starting point, there's a checkpoint on [Hugging Face](https://huggingface.co/nnandal/niels-gpt).

## the tradeoffs (what I intentionally didn't do)

- **no flash attention / fused kernels** - this is not a performance-obsessed CUDA repo. It's a correctness + clarity repo that still runs fast enough to iterate
- **no distributed training** - again: laptop-first. The architecture decisions stay valid; the infra can be swapped later
- **no quantization / serving stack** - inference is implemented, not "productionized". If you want vLLM/TensorRT-LLM, this isn't competing. It's teaching you the underlying mechanics
- **some paper cuts remain** - e.g. "build-all" covers the big sources; a couple smaller paths (like primer caching) are still deliberately manual so the naming + metadata story stays explicit

These aren't accidents. They're scope boundaries.

## why this matters (beyond "I can train a toy model")

A lot of layers to connect:

- tokenization choices → context length pressure → attention cost
- data mixing → loss curves → model behavior
- chat formatting + special tokens → SFT masking → alignment outcomes
- kv-cache correctness → latency + product experience

`niels-gpt` is built to keep those causal links visible. It's how you build intuition *and* ship a system you can trust.

You get a clean sandbox to test architectural swaps (norms, MLP type, RoPE theta, masking policies) without reverse-engineering a framework stack.

## closing

The point of this repo is not to impress you with parameter counts. It's to show that I can take an LLM system from raw text to a chatting checkpoint, with strong guardrails, in a way that stays readable under pressure.

If you're building LLM infra, you want engineers who can move fast *and* keep the failure modes crisp. This is my proof-of-work.
