Factory Simulator turns a paragraph of prose about a factory into a schedule.
LLM agents parse the description into a typed config, a deterministic
[EDD job-shop simulator](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/sim.py)
runs one to three scenarios over it, and a briefing explains the metrics. The
[use case](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/README.md)
is the planner's morning question: what will go wrong today, and which jobs
are at risk.

It began as a fixed ten-stage pipeline. On 2025-12-03 I
[replaced it](https://github.com/NielsdaWheelz/factory-simulator/commit/bc96eaa8bda9c10b05cd3f8577b82b06395f0532)
with a plan-then-execute agent: the model emits a typed plan, and a
deterministic engine executes that plan against a
[tool registry](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/agent_tools.py)
under max-step and LLM-call budgets, returning a partial answer when a budget
runs out. The alternative was adopting LangGraph; the in-repo
[demo script](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/DEMO.md)
instead maps each hand-rolled piece to its LangGraph equivalent. The
orchestrator shrank to a 31-line wrapper.

Two guards make the parsing checkable. Before any LLM call,
[regex extraction](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/onboarding.py)
pulls the machine and job IDs the text states explicitly; the model's parse
is then measured against that ground truth, so a dropped or invented machine
is a number, not a suspicion. And every LLM response passes through
[one choke point](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/llm.py):
OpenAI JSON mode into a Pydantic schema. `openai` is imported inside that
function, so the test suite monkeypatches the boundary and runs without an
API key or the package installed.

Evaluation is a
[13-case adversarial corpus](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/eval/adversarial_cases.yaml)
of clean, messy, and hostile factory texts, checked against
[structural invariants](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/eval/invariants.py)
rather than golden outputs: valid machine references, minimum durations,
non-empty jobs. The React frontend renders the agent's plan, its data flow,
and the LLM call log beside the answer.

Numbers, from git log and AST counts at HEAD: 93 commits from 2025-11-19 to
2025-12-06; 419 test functions across
[20 backend files](https://github.com/NielsdaWheelz/factory-simulator/tree/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/tests);
zero frontend tests.

What is wrong with it is mostly what the rewrite left behind. The README documents
the pre-rewrite system: it describes `POST /api/simulate`, and the
[server](https://github.com/NielsdaWheelz/factory-simulator/blob/46c3eef18829c7751e2b82cc332f74eb93ee79ff/backend/server.py)
exposes only `POST /api/agent`. The CLI imports a function the rewrite
deleted, so `python -m backend.main` raises ImportError. The backend has no
dependency manifest, and there is no CI. Determinism holds only for the
scheduler core — the LLM calls set no temperature and no seed. The fallback
policy contradicts itself: a demo-factory tool coexists with a system prompt
that forbids silently using it.

The core still cannot invent a schedule. Everything around it drifted in
three weeks.
